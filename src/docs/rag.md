# RAG (Retrieval-Augmented Generation)

**RAG** — способ отвечать на вопросы с помощью LLM, подмешивая во внешний контекст релевантные фрагменты из своей базы знаний (документы, FAQ, код, внутренние wiki).

Модель не «помнит» ваши данные. У неё ограниченное окно контекста и устаревшие знания. RAG решает это так: в момент запроса система **ищет** нужные куски и **передаёт** их модели вместе с вопросом.

## Зачем это нужно

- Ответы опираются на ваши документы, а не только на обучение модели.
- Можно ссылаться на источники.
- Базу можно обновлять без переобучения модели.
- Меньше галлюцинаций на корпоративных и узкоспециальных вопросах.

## Как это работает

Два этапа.

### 1. Индексация (один раз / по расписанию)

1. Загрузить документы (PDF, Markdown, Confluence, БД).
2. Разбить на **чанки** — небольшие фрагменты, которые помещаются в контекст.
3. Превратить чанки в **эмбеддинги** (векторы смысла).
4. Сохранить векторы в **vector store** (Chroma, Qdrant, PGVector, Pinecone и т.д.).

Похожие по смыслу тексты оказываются рядом в векторном пространстве.

### 2. Ответ на вопрос (каждый запрос)

1. Вопрос пользователя тоже превращается в эмбеддинг.
2. Из хранилища достаются ближайшие чанки (**retrieval**).
3. LLM получает: вопрос + найденные фрагменты.
4. Модель генерирует ответ на основе этого контекста (**generation**).

```text
Документы → чанки → эмбеддинги → vector store
                                        ↑
Вопрос → эмбеддинг → поиск похожих чанков → LLM → ответ
